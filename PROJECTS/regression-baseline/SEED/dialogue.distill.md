# Seed: 对话蒸馏 — 我们对"底座"的共识

> 来源：用户与 AI 的平等探讨记录（2026-09）。这是 BASE 设计哲学的根。

## 核心共识

1. **三个资料都是"语境化产物"，不是普适底座**
   - mattpocock = 优秀工程师的影子
   - Scaling = 特定任务分布上的经验规律
   - 两者都应随项目经验被调整、重写、淘汰

2. **"优秀角色"因项目而异**
   - 不限于工程师，可能是任何"标准化流程执行者"
   - 固定思维流 / 工作步骤，可独立于编程能力存在

3. **真正可复用的是"元流程"，不是内容**
   - raw → wiki → skill → gate → rollback
   - 内容层（角色/技能/规则）全部可替换

4. **演化机制自身也可被演化**
   - 元流程的每一步（pattern 怎么写、验证集怎么留）也可能带偏见
   - 最稳定的底座 = "具备自我观察与自我修正能力的循环"本身
   - 任何 seed（含本文件）都不应设为不可修改

5. **常驻复制式底座**
   - BASE 是最新镜像，新项目 `new_task.sh` 复制独立工作区
   - 项目结束通过 PROPOSAL + GATE 回填 BASE → 打 tag
   - 下一轮复制即获得累积遗产

6. **自举第一轮的诚实局限**
   - 无历史数据时只能验证"能跑"，不能验证"优秀"
   - "通用"需靠后续多领域项目校准，第一轮不追求完美

## 由此导出的设计决定

- 宪法（CONSTITUTION）只写元原则 + 可演化条款
- 门控（GATE）强制跨领域复用验证 + 回归 + 回滚
- 回归集（REGRESSION）刻意跨领域（软件/运营/合规/迁移）
- 宪法修正案需双倍验证，保留旧 tag
