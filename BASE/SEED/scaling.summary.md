# Seed: Towards a Science of Scaling Agent Systems

> 来源：https://arxiv.org/abs/2512.08296 （Google / MIT 等，受控实验 180-260 组配置）
> 定位：**架构选型经验规律**，非定律。作为 route-intake 的**初始假设集**，可被项目数据校准/推翻。

## 核心结论（受控实验，特定任务分布）

- 可并行、可分解任务（多维度分析等）→ 集中编排有增益
- 强串行规划 / 逐步依赖推理 → 多加 agent 反而降效
- 工具重、消息多的任务 → 协调开销吃掉推理预算
- 无集中校验的独立 agent → 错误放大最严重
- 单 agent 基线已较强后 → 再加协调边际递减甚至负收益（能力饱和）

## 转化为 route-intake 的可测属性（假设，非规则）

| 属性 | 含义 | 倾向 |
|---|---|---|
| 并行度 | 能否拆成独立单元 | 高 → 考虑集中编排 |
| 串行依赖 | 下一步是否强等上一步结论 | 高 → 优先单 agent |
| 工具密度 | 单位任务的外部调用数 | 高 → 控制 agent 数 |
| 错误代价 | 出错后果严重性 | 高 → 必须集中校验 + 回放 |
| 可独立验证 | 子结果能否单独判对错 | 高 → 可派发专家 |

## 作为种子的姿态

- ✅ 提供**架构假设的初始维度**（上面这张表）
- ✅ 提供"先测单 agent 基线，再考虑加人"的保守默认
- ❌ **不是静态规则库** —— 项目积累真实数据后应实时校准各阈值
- ❌ 不强制多 agent；默认单 agent，证据充分才拆分
- route-intake 输出的拓扑建议仅为**待验证假设**，落地后由轨迹反馈修正
