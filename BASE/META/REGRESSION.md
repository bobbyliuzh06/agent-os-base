# 回归验证设计 — 通用能力六维完整验证细则（v0.1 自举候选）

> 本文件补全 `META/REGRESSION.md` 的缺口：原文件只给六维各 0–2 分、单探针 ≥9/12、全探针均分不降，
> **未定义第六维"演化规程"的独立、可操作验证方式**（环境自检发现，本设计轮已确认）。
> 本细则定性为 v0.1 自举候选；首版无历史基线，不宣称"已通用"。

---

## 一、六维定义与通用打分标准（0/1/2 各档）

### 维 1 任务理解
- **0**：无目标/边界/成功标准，或明显错误；未做需求澄清
- **1**：有目标与边界，但成功标准不可验证，或缺"明确不做什么"
- **2**：目标、边界、可验证成功标准、"明确不做"清单齐备且相互一致

### 维 2 可验证执行
- **0**：无拆解，或拆解无法验收
- **1**：有拆解，但部分工作单元无验证判据，或缺失败预案
- **2**：全部工作单元有验收判据 + 失败预案 + 验证顺序合理

### 维 3 失败诊断
- **0**：无诊断路径（跳过分析直接给对策）
- **1**：有假设，但缺复现/最小化条件或验证步骤
- **2**：复现条件 → 最小化假设 → 根因分类 → 逐条验证，闭环完整

### 维 4 边界控制
- **0**：无边界声明，或已越界执行
- **1**：有边界，但高危操作无 HITL 清单、不可逆决策无记录要求
- **2**："不做什么"明确 + 高危操作 HITL 清单 + 不可逆决策留痕要求齐备

### 维 5 跨领域迁移
- **0**：全程领域专有措辞，无抽象
- **1**：有抽象尝试，但重述后仍含领域名词，或抽象后失去可操作性
- **2**：触发/步骤/回滚可全文无领域名词重述，且仍可执行（领域无关重述测试通过）

### 维 6 演化规程 — 独立验证细则（本设计轮补全，见下节）

## 二、第六维"演化规程"独立验证方式（核心缺口补全）

第六维不使用单一笼统打分，而是由三项**可机械查验**的子检查 E1/E2/E3 合成，并设**独立附加门槛**。

### 2.1 子检查定义

**E1 留痕完整性**（机械可查，不需判断力）
- **2**：`WORKSPACE/raw/` 轨迹文件存在，且含技能版本戳、失败记录、人工反馈字段，三者齐备
- **1**：轨迹文件存在且含技能版本戳，但缺失败记录或人工反馈之一
- **0**：无轨迹文件，或缺失技能版本戳

**E2 底座适配判断**（查路由记录）
- **2**：路由记录含适配结论 + 理由；且若不适配，给出修改对象类型（pattern|skill|architecture|constitution）
- **1**：有适配结论，但缺理由或缺修改对象类型
- **0**：无适配判断

**E3 回填建议质量**（查任务结束的演化回填动作）
- **2**：回填建议含类型 + 证据链（真实轨迹链接或如实标注的冷启动声明）+ 验证方案 + 回滚说明，可执行
- **1**：有建议但缺以上四项之一，或不可执行
- **0**：无回填建议，或纯空话

### 2.2 维得分规则（方案 A：直接取 E1 值，人工 Gate 复审后修订）

```
维得分 = E1（0/1/2 直接取 E1 值）
```

读法说明：E2/E3 不参与维得分合成，仅作用于 §2.3 附加门槛（E2+E3 合计 = 0 → 维得分强制 0 且探针判不过）。五个探针"演化规程"锚点中的 E2/E3 表述均对应 §2.3 硬卡条件而非得分调节项，与本节公式一致，锚点文字无需改动。

### 2.3 附加门槛（放宽版，本轮人工确认；独立于总分之外）

1. **E1 = 0 → 维得分强制 0，且该探针判不过**（无留痕即无演化证据，其余各维满分也无效）；
2. **E2 + E3 合计 = 0 → 维得分强制 0，且该探针判不过**（既无适配判断又无回填建议，演化闭环断裂）；
3. 附加门槛不过 → 探针整体失败，**即使六维总分 ≥9/12 也不通过**。

### 2.4 为何"独立"而非"演化回填建议顶替"

- 原 REGRESSION.md 的"演化回填建议"只是产出物清单项，无打分、无门槛、无查验手段；
- E1 是文件级机械检查（有/没有，可脚本化），E2/E3 是内容级检查（有/无 + 完整度）；
- 附加门槛保证演化闭环的最低存活条件，且不依赖任何"质量感"主观判断。

## 三、探针集（5 个，含 3 个非软件）

通过判据：**单探针六维总分 ≥9/12 且附加门槛通过**；全探针集均分不低于上一版 BASE（不降回归）。

### 探针 P1 — 软件领域（基线对照）

- **领域**：软件工程
- **输入**：为一个命令行待办工具（增删改查、完成标记、本地存储）设计 v0.1 开发计划
- **预期产出（可验证判据）**：
  - CONTEXT：目标/边界/成功标准/不做什么，四要素齐备
  - 垂直切片 issue 列表：每个切片可独立验收
  - TDD 验证判据：先失败测试后实现
  - ADR：记录存储选型（附备选与被否决理由）
  - 显式声明"不做 Web UI"
- **六维打分锚点**：
  | 维 | 0 | 1 | 2 |
  |---|---|---|---|
  | 任务理解 | 无边界或目标含糊 | 有目标边界但成功标准不可验证 | 四要素齐备且"不做 Web UI"显式 |
  | 可验证执行 | 无 issue 拆解 | 有拆解但部分不可独立验收 | 垂直切片 + 每片 TDD 判据 + 失败预案 |
  | 失败诊断 | 无诊断路径 | 有假设无复现/最小化 | 复现→最小化→假设→插桩验证闭环（如存储损坏复现脚本） |
  | 边界控制 | 无边界 | 有边界但 ADR 缺失 | out-of-scope 明确 + ADR + 数据删除等高危操作 HITL 清单 |
  | 跨领域迁移 | 纯软件术语 | 有抽象但依赖"测试环境"等软件前提 | 方法可无领域名词重述（基线对照用途） |
  | 演化规程 | E1=0 | E1=1 或 E2/E3 不全 | E1=2 且 E2/E3 达标（按 §2 合成） |

### 探针 P2 — 供应链中断响应预演（制造业，非软件）

- **领域**：制造业供应链
- **输入**：一家电子制造企业，关键物料依赖单一供应商，该供应商突发停产 3 周。设计"中断响应预演流程"（推演 + 验证 + 预案）
- **预期产出（可验证判据）**：
  - 现象/推演条件：停产时间线、波及产线与在途库存状态，可复现推演
  - 最小化假设：影响范围分级（仅 A 产线 vs 全厂停线）
  - 根因分类：供应商/物流/库存/需求侧，各有一类
  - 每条对策有验证判据（例：安全库存覆盖天数 ≥ 停产周期；替代料认证时长 ≤ X 天）
  - 明确不做：不全面切换供应商、不借高息贷款囤料
- **六维打分锚点**：
  | 维 | 0 | 1 | 2 |
  |---|---|---|---|
  | 任务理解 | 无推演范围或目标含糊 | 有范围但"响应达标"不可验证 | 推演条件 + 达标判据 + "不做什么"齐备 |
  | 可验证执行 | 无对策拆解 | 有对策但部分无验证判据 | 每条对策有可量化判据（库存天数/认证时长）+ 失败预案 |
  | 失败诊断 | 直接给对策无分析 | 有假设但无最小化（未分级影响范围） | 复现推演 → 影响分级 → 根因四分类 → 逐条验证闭环 |
  | 边界控制 | 无边界 | 有边界但缺"极端情况不做什么" | out-of-scope 明确 + 大额采购/切换供应商等 HITL 清单 |
  | 跨领域迁移 | 全文供应链术语 | 有抽象但重述仍含"供应商/产线" | 触发/步骤/回滚可无领域名词重述（如"关键依赖中断响应"） |
  | 演化规程 | E1=0 | E1=1 或 E2/E3 不全 | E1=2 且 E2/E3 达标（按 §2 合成） |

### 探针 P3 — 员工报销审批（合规/流程，非软件）

- **领域**：合规与流程管理
- **输入**：为一家 50 人中小企业设计"员工报销审批"标准化流程与异常处置
- **预期产出（可验证判据）**：
  - 角色分工：申请人/审批人/出纳/审计，各角色权限清单
  - 规则：单据、金额、时效规则可执行（例：>X 元须两级审批）
  - 异常处置分支：超标/重复/虚假，各分支有明确处置路径
  - 审计留痕：每笔报销可追溯到单据与审批人
  - 明确"单人不得兼任审批与出纳"（职权分离）
- **六维打分锚点**：
  | 维 | 0 | 1 | 2 |
  |---|---|---|---|
  | 任务理解 | 无流程范围或规则含糊 | 有范围但"合规通过"不可验证 | 角色/规则/异常/留痕齐备 + 成功标准可验证 |
  | 可验证执行 | 无流程拆解 | 有流程但异常分支缺处置 | 三分支处置完整 + 每条规则有判据 + 失败预案 |
  | 失败诊断 | 无异常分析路径 | 有异常假设但缺分类 | 复现（单据样本）→ 最小化 → 超标/重复/虚假分类 → 验证 |
  | 边界控制 | 无边界 | 有边界但缺职权分离声明 | "单人不得兼任审批与出纳"显式 + 高危（垫付/大额）HITL |
  | 跨领域迁移 | 全文报销术语 | 有抽象但重述含"单据/报销" | 可无领域名词重述为"凭证审批职权分离流程" |
  | 演化规程 | E1=0 | E1=1 或 E2/E3 不全 | E1=2 且 E2/E3 达标（按 §2 合成） |

### 探针 P4 — 内容运营复盘（非软件）

- **领域**：内容运营
- **输入**：一档周更栏目连续三周打开率下滑 40%，设计诊断与改版流程
- **预期产出（可验证判据）**：
  - 指标拆解：打开率 = 触达 × 标题 × 首屏，拆解可验证
  - 最小化假设：渠道 / 选题 / 发布时段，至少三选一排序
  - 每条对策有验证判据：A/B 对照组、样本量、观察周期（例：单组 ≥ 500 曝光、观察 ≥ 2 周）
  - 明确不做：不整体换风格、不买量
- **六维打分锚点**：
  | 维 | 0 | 1 | 2 |
  |---|---|---|---|
  | 任务理解 | 无诊断范围或指标含糊 | 有范围但"下滑原因"不可验证 | 指标拆解 + 可验证判据 + "不做什么"齐备 |
  | 可验证执行 | 无对策拆解 | 有对策但无 A/B 判据 | 每条对策有对照组/样本量/观察周期 + 失败预案 |
  | 失败诊断 | 直接改版无分析 | 有假设但未最小化 | 复现（三周数据）→ 最小化假设 → 分类 → 逐条验证 |
  | 边界控制 | 无边界 | 有边界但缺"不买量"类声明 | out-of-scope 明确 + 对外发布等高危操作 HITL |
  | 跨领域迁移 | 全文运营术语 | 有抽象但重述含"打开率/选题" | 可无领域名词重述为"指标下滑诊断与改版流程" |
  | 演化规程 | E1=0 | E1=1 或 E2/E3 不全 | E1=2 且 E2/E3 达标（按 §2 合成） |

### 探针 P5 — 跨领域迁移（最难）

- **领域**：跨领域（供应链 → 软件）
- **输入**：把 P2 的"中断响应预演"抽象为可复用的通用技能 SKILL.md，并验证能在软件场景（依赖包安全漏洞应急）复用
- **预期产出（可验证判据）**：
  - SKILL.md 通过"领域无关重述测试"：触发/步骤/回滚全文无领域名词
  - 软件实例化可执行：触发 = 漏洞披露；步骤 = 复现/最小化/假设/验证/预案；回滚 = 回退依赖版本
  - 两个场景各一份实例化记录（供应链 + 软件）
- **六维打分锚点**：
  | 维 | 0 | 1 | 2 |
  |---|---|---|---|
  | 任务理解 | 无抽象目标或验证场景缺失 | 有抽象但场景实例化不可执行 | 两场景实例化可执行 + 判据明确 |
  | 可验证执行 | 无 SKILL 结构 | 有结构但步骤无判据 | 每步有判据 + 两场景失败预案 |
  | 失败诊断 | 无诊断步骤 | 有步骤但无最小化 | 复现→最小化→假设→验证在两场景均可执行 |
  | 边界控制 | 无回滚 | 有回滚但场景不成立 | 两场景回滚均可执行（回退依赖版本/恢复供应） |
  | 跨领域迁移 | 未通过重述测试 | 重述后仍含领域名词 | **通过领域无关重述测试（本维 2 分的必要条件）** |
  | 演化规程 | E1=0 | E1=1 或 E2/E3 不全 | E1=2 且 E2/E3 达标（按 §2 合成） |

## 四、通过判据与基线建立

1. 单探针：六维总分 ≥9/12 **且** 附加门槛通过（§2.3）；
2. 全探针集：均分不低于上一版 BASE 得分（满足 GATE"不降回归"）；
3. **首版基线**（本轮冷启动）：无历史基线可比 → 由人工在合并时试跑一次建立 v0.1 基线，产物落盘 `BASE/regression-runs/`；本设计轮**不宣称试跑已发生**；
4. 第六维附加门槛阈值为 v0.1 候选值，随真实项目数据校准（校准走 GATE 级 B）。

## 五、探针集维护与轮换

- 每次宪法修正案后或每 3 轮回填（v0.1 假设值，待校准），审查探针集是否仍覆盖原定领域分布；
- 轮换须记录理由与新旧探针对照，防止"为探针优化"（探针集不进 wiki 蒸馏输入，只作验证）；
- 各轮探针得分与 BASE 版本 tag 绑定，旧基线永远可回退比对（防 `meta-loop-bias`）。

## 六、反工程师人格污染措施（本探针集如何保证非软件领域被真正覆盖）

1. **输入/产出/判据全部用领域原语书写**：P2/P3/P4 的预期产出中无一条要求"写代码/开 issue/CI"；
2. **打分锚点禁止奖励软件术语**：非软件探针中照搬 TDD/ADR/issue 措辞不加分；若因此丢失领域可操作性，按对应维度降档；
3. **P5 强制领域无关重述测试**：跨领域迁移维 2 分的必要条件，直接检验"抽象是否剥离了工程师人格"；
4. **执行入口约束**：探针任务执行前必须先走 route-intake 的"领域抽象映射"（见改进版技能第 3 步）；
5. **观察指标**：每轮试跑记录"术语越界"次数，作为 `seed-persona-lock` 与 `meta-loop-bias` 的观测数据。
