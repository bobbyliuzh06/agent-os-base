# CONSTITUTION.md — 演化底座元宪法

> 本文件定义底座不可轻易绕过的元原则。修改需走"宪法修正案"流程（见 GATE.md）。

## 核心条款

**1. 内容层可替换**
角色定义、技能、架构规则、领域知识均为**临时假设**，可随项目经验被挑战、修改、替换。种子资料（mattpocock / WikiSkill / Scaling）是首批假设，**不是教义**。

**2. 元流程相对稳定**
演化循环：`轨迹采集 → 模式提取 → 技能/规则提案 → 门控验证 → 回滚`。
此循环本身是底座的主引擎；即使具体内容全换，循环结构应优先保留。

**3. 执行与经验隔离**
执行 agent 只加载**当前生效技能**；经验库（wiki/raw）仅给维护者与提案者使用。
禁止执行 agent 直接读 wiki 抄答案 —— 会导致轨迹信息量下降、后续技能演化退化。

> **新架构对应物（AMEND-20260913-01，宪法修正案批准）**：14 阶段管线运行时执行的是
> 硬化后的脚本（脚本=技能硬化产物）；skills 层作为经验蒸馏的落点保留。蒸馏路径
> （轨迹→模式→技能→脚本）每轮 reflow 检视一次并记录答案；连续 3 轮检视零蒸馏时，
> 展示站须如实标注"经验蒸馏停转中"。以"裁定"替代宪法修正案不成为先例。

**4. 演化机制自身也可被演化**
当跨项目证据显示元流程某步产生偏见或低效，可提**宪法修正案**。
但需满足：交叉验证 + 人工复审 + 保留旧版本 tag（双倍验证，见 GATE.md）。

**5. 非工程师角色同样适用**
底座面向"标准化流程执行者"，不限于程序员。
用"固定思维流 / 工作步骤"替代"写代码工作流"作为种子抽象；工程师技能只是其中一种人格。

**6. 回填必须可溯源、可回滚、可跨领域复用验证**
任何进入 BASE 的内容都要附带证据链，且能在非原领域复用验证。

## 派生约束（由条款推出，执行期必须遵守）

- 执行 agent 不自动放宽高危权限（删除 / 外发 / 凭据 / 生产操作），一律 HITL
- 种子内容不得设为"不可修改项"
- 单 agent 基线未测前，不默认拆多 agent
- 所有不可逆决策记录 ADR，附备选方案与被否决理由
- 版本化：BASE 为 git 仓库，每次回填打 tag，可回滚

## 宪法修正案流程

1. 提案者写 `PROPOSAL.md`，类型 = `constitution-amendment`
2. 附 ≥2 个跨项目证据 + 跨领域探针验证
3. 人工复审（用户本人）
4. 通过后：保留旧 tag，新建 tag，更新本文件与 CHANGELOG
5. 拒绝的修正案归档至 `ARCHIVE/`，pattern 保留供再评估
