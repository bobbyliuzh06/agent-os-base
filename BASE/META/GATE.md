# GATE.md — 回填门控标准

> 所有进入 BASE 的 PROPOSAL 必须逐条自检并通过。任一条不满足即拒绝（拒绝≠删除，归档至 ARCHIVE/）。

## 通用门槛（任何提案都必须满足）

- [ ] **证据链**：附 ≥ 1 条真实项目原始轨迹（脱敏）到 `WORKSPACE/raw/`，并链接至提案
- [ ] **跨领域复用**：在 ≥ 1 个**非原领域**探针任务上复用成功
  - 例：原领域是软件 → 探针用运营 / 合规 / 供应链等
- [ ] **不降回归**：不降低上一版 BASE 在 `META/REGRESSION.md` 回归集上的通过率
- [ ] **可回滚**：附带回滚方案（git revert 或旧 tag），且不破坏既有项目
- [ ] **不削弱铁律**：不绕过 HITL、不开放高危权限、不直连经验库抄答案

## 分级门槛

### A. 新技能 / 技能修改（最常见）
- 满足通用门槛
- 有清晰的 `whenToUse` 触发条件 + 步骤 + 回滚说明
- 在 ≥ 2 个项目轨迹中出现复用价值（避免为一次性需求建技能）

### B. 架构规则修改（如 route 机制、并行度阈值）
- 满足通用门槛
- 附 before/after 对比 + 协调开销、错误放大指标
- 经 ≥ 1 个多步骤任务验证

### C. 宪法 / 元流程修改（最严）
- 满足通用门槛 **全部**
- **双倍验证**：交叉验证 + 人工复审（用户本人）
- 保留旧版本 tag，更新 CHANGELOG
- 过渡期（≥ 1 个项目）双轨运行，确认新流程不劣于旧流程

## 自动拒绝项（无需讨论）

- 放宽高危权限（删除 / 外发 / 付费 / 凭据 / 生产写）
- 让执行 agent 直接读 wiki 抄答案
- 无任何轨迹证据的纯理论提案
- 降低回归集通过率的提案
- 把任一 seed 设为不可修改项

## 回填操作

```bash
cd agent-os/BASE
# 人工审核 PROPOSAL.md 通过后
cp ../PROJECTS/<name>/PROPOSAL.md governance/    # 归档提案
# 合并技能/模板/经验 → 更新 META/VERSION + CHANGELOG
git add -A && git commit -m "apply <name> proposal"
git tag v<new_version>
```
