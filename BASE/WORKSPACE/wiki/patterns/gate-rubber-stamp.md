# PATTERN — 门控橡皮图章（gate-rubber-stamp）

## 类型
anti-pattern

## 现象（可观察的表现）
- 提案自检清单全勾、被接受，但找不到任何回归试跑产物；
- 回归只跑原领域 happy path，探针失败被解释掉而非记录；
- 提案人与审核人是同一个 agent（或自检即终审）。

## 触发条件（何时会出现）
- Gate 角色缺失或折叠进提案流程（现 BASE 无独立 gate 技能，Gate 职责在 propose-gate 自检 + 人工）；
- 时间压力下"快点合入"；
- 门控条款不可操作："不降回归"未定义跑哪些探针、记录落在哪里、谁跑。

## 根因
- 自评利益冲突：提案人天然偏向自己通过；
- 条款缺操作化判据，自检沦为勾选框仪式；
- 无独立审核者 + 无落盘产物 = 无物可查。

## 应对措施（可复用的步骤/规则）
1. **提案人与审核人分离**（铁律级）：`gate-review` 职责严格限定为跑探针、记 before/after、出 accept/reject/archive，不做自评；同一会话不得兼任两者；缺独立审核者时由人工（用户）任 Gate；
2. 回归试跑产物强制落盘 `WORKSPACE/regression-runs/`，裁定必须引用产物文件；
3. 自动拒绝项机械核验（不依赖判断力：高危权限/抄答案/无证据/降回归/种子不可修改）；
4. 审核痕迹（谁、何时、裁定、依据）写入 `wiki/skill-impact.md`，可追溯。

## 适用条件与例外
- 人工（用户）审核不触发本 pattern（人工是最终裁决者）；
- 无独立审核者时由人工担任 Gate，不允许"自己审自己"。

## 证据轨迹
> 冷启动声明：无真实项目轨迹。构造性自指证据：本轮环境自检发现现 BASE 无独立 Gate 技能、GATE 条款无落盘产物要求——即本 pattern 的一例真实构造（缺陷已在 `WORKSPACE/PROPOSAL.md` 上报）。回补期限见 PROPOSAL.md。

## 跨领域适用性评估
- 原领域：软件工程治理（code review / CI 门禁）
- 可迁移至：财务审批（申请人≠审批人）、合规复核、质量门禁——一切"自检放行"场景的职权分离原则
- 抽象层级：高（职权分离 + 产物落盘的可审计原则）
