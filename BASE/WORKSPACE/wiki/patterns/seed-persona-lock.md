# PATTERN — 种子人格固化（seed-persona-lock）

## 类型
anti-pattern

## 现象（可观察的表现）
- 非软件任务（供应链、合规、运营）的产出布满 TDD / ADR / issue / CI 等软件术语；
- CONTEXT.md 用"垂直切片"描述供应链任务、用"红绿重构"描述报销流程；
- 执行 agent 默认以工程师人格工作，把"写代码工作流"当唯一抽象。

## 触发条件（何时会出现）
- 冷启动期：种子资料全部来自软件领域（mattpocock 摘要即"优秀工程师的影子"）；
- 执行者未做领域抽象，直接沿用种子措辞；
- 用户未指定执行角色，agent 回落到熟悉的工程师人格。

## 根因
- 种子是"语境化产物"，不是普适底座（dialogue 共识 1）；
- 技能与模板写作时未剥离"写代码"语境，"抽象"停留在类比而非结构层面；
- 缺一个强制性的"领域等价物映射"步骤挡在种子与产出之间。

## 应对措施（可复用的步骤/规则）
1. `route-intake` 强制"领域抽象映射"步骤：软件概念 → 通用思维流 → 领域等价物，三列对照后才允许进入计划；
2. 非软件任务的输入/产出/判据一律用领域原语书写（打分锚点禁止奖励软件术语）；
3. 探针集刻意跨领域（供应链/合规/运营），回归时记录"术语越界"次数作为观察指标；
4. 定期把 seed 与 wiki 对照，标记"已被项目经验覆盖/待替换"的种子项（种子永非不可修改）。

## 适用条件与例外
- 软件领域任务不触发；
- 用户明确要求软件工作流（如"按 TDD 写这个工具"）时允许，但须在 CONTEXT 中显式声明。

## 证据轨迹
> 冷启动声明：无真实项目轨迹。依据 = `SEED/dialogue.distill.md` 共识 1/2 + `SEED/mattpocock.summary.md`"剥离写代码语境"的自指要求 + 本轮设计自检（本 pattern 与全部交付物以领域原语书写）。回补期限见 PROPOSAL.md。

## 跨领域适用性评估
- 原领域：软件工程
- 可迁移至：运营 / 合规 / 供应链 / 内容 / 教育等一切非软件领域
- 抽象层级：高（技能与模板的写作规范，领域无关）
