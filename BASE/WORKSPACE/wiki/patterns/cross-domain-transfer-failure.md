# PATTERN — 跨域迁移静默失败（cross-domain-transfer-failure）

## 类型
failure

## 现象（可观察的表现）
- 某技能在原领域验证通过、进入 BASE，但在非原领域探针上静默失败；
- 技能步骤"看起来通用"，实则携带原领域前提（例："先写失败测试"隐含存在可自动运行的验证环境）；
- 失败不报错、不崩溃，只是产出不合格——比显式失败更难发现。

## 触发条件（何时会出现）
- 只有单领域证据就回填 BASE；
- 抽象靠类比完成（"TDD → 验收判据"字面替换），未做结构检验；
- GATE 的跨域探针被跳过、走过场或只跑 happy path。

## 根因
- 抽象层级错误：太低 = 保留领域名词与前提；太高 = 丢掉可操作性（"先分析再执行"式空话）；
- 缺少一个可操作的"领域无关重述测试"来锁定正确抽象层级。

## 应对措施（可复用的步骤/规则）
1. GATE 通用门槛强制：≥1 个非原领域探针复用成功才可回填（已有条款，本 pattern 指出其可被走过场，须配合 gate-review 的落盘产物核验）；
2. 抽象层级测试（`trace-distill` 第 4 步）：pattern 的"触发/步骤/应对"必须能**全文无领域名词重述且仍可执行**，否则标注领域限定；
3. 探针集定期轮换，防"为探针优化"（针对固定探针微调技能）；
4. 跨域失败案例归档为 pattern 而非静默丢弃（失败经验永久保留，wiki 不回滚）。

## 适用条件与例外
- 明确声明"仅限某领域"的技能可豁免跨域门槛，但不得进入通用技能目录；
- 首版冷启动的跨域验证只能以探针设计替代（如实标注，设回补期限），不得冒充已完成。

## 证据轨迹
> 冷启动声明：无真实项目轨迹。依据 = `META/GATE.md` 跨域条款的自指风险分析（条款存在但缺操作化验证手段）+ `SEED/dialogue.distill.md` 共识 3（真正可复用的是元流程不是内容）。回补期限见 PROPOSAL.md。

## 跨领域适用性评估
- 原领域：任一领域（技能产出地）
- 可迁移至：所有领域（本 pattern 描述的是验证方法本身）
- 抽象层级：高（可操作的抽象层级检验）
