## 0. 定位与三条铁律

- **定位**：Project = 任务宿主 + 记忆体 + 责任体。task 是"一次交付"，Project 是
  "一个需要被持续照顾的对象"（投资组合、网站、游戏、底座自身）。
- **三条铁律**：
  1. **记忆先于智能** —— 没有假设台账/决策日志/教训库，迭代只是空转重跑；
  2. **真值先于自动化** —— 外部真值（市场/流量/用户反馈）是演化适应度信号；
     接不上真值的场景必须显式降级为"文档生成"，不得冒充自驱演化；
  3. **人机分界按风险** —— 纸面/草稿可自动，真钱/线上发布必须人工。
- **已裁定**（任务层实践中确认）：
  - 真值源：历史回放优先，近实时为增强项（可复现 > 真实感）；
  - 节奏：白名单模板（daily/weekly/event），新节奏 = 模板注册 + 门禁；
  - 记忆：决策日志只追加不可改；假设可修订但修订 = 新条目 + 前向引用；
  - 落点：先任务层草稿，BASE 化走提案门禁；
  - 投资案例验收 = 过程纪律而非收益；charter 强制"研究工具，不构成投资建议"；
  - **评估与回写是机制级原语**（2026-09-13 讨论裁定）：任何持久化项目管理都内建
    "信号→痛点→行动→验证→回写"回路；变化的是**评估域**（见 2.7），由 charter 声明，
    表象随场景（投资=绩效评估；网页按目的=访问量/转化/留存/美工评审；底座=过程健康）；
  - **独立性是机制级要求**（2026-09-13 落地）：单人闭环自评必须由两条独立路径制衡——
    确定性证据验证器 + 角色分离复核人；复核收敛判定必须人工裁决，不得自证；
  - **台账写入机械化**：append-only 台账的追加必须经唯一行身份助手（row_id=id#行序），
    禁止手工拼接追加；历史行只读不可回写，修正=追加引用行号。

## 1. 概念模型

### 1.1 七要素

| 要素 | 定义 | 最小载体 |
|---|---|---|
| 持久身份 | 项目唯一 ID + 名称 + 使命一句话 | charter.id/name/mission |
| 章程 | 目标、基准、约束、风险预算、审批点、节奏、真值源声明、**评估域声明** | charter.yaml |
| 记忆 | 假设台账 + 决策日志 + 教训库 + **痛点台账** | memory/（append-only 核心区） |
| 真值 | 外部适应度信号，只读、完整性校验、失效降级 | truth/ 接口 + 校验记录 |
| 节奏 | 白名单周期模板驱动的循环 | cycle/ 配置 + 调度注册 |
| 策略 | 领域化安全策略与审批点 | policy/（继承底座四锁语义） |
| 审计 | 决策链完整可回溯（为什么/依据/结果/是否兑现） | audit/ + 与供应链台账同风格 |

### 1.2 生命周期

```
诞生（charter 审议，走门禁）
  → 运转（cycle 循环：观察→提议→gate→沙箱执行→记录→复盘）
  → 演化（charter/策略自修订，必须走门禁）
  → 退役（仅人工；audit/ 与 memory/ 归档保留）
```

### 1.3 与现有层的关系

- Project ⊃ tasks：每周期"提议+执行"落地为一个 task 实例，Project 负责记忆与责任。
- Project 自修订与 BASE 提案共用同一套裁决哲学（规则层优先、四锁、人工合并）。
- 七阶段管线（BASE 演化）就是"案例③"的雏形；2026-09-13 起管线已接管 Project 层的
  体检/站点生成/证据验证/独立复核/过程回归（现为 10 阶段，见 4.1）。

## 2. 核心组件规格

### 2.1 charter.yaml（字段级草案）

```yaml
id: portfolio-cn300            # 持久身份
name: 沪深300 纸面投资经理
mission: 以纪律化、可解释的决策过程，长期维护组合并持续迭代策略
baseline: 沪深300 指数
constraints:                   # 硬约束（gate 层强制）
  - 纸面交易 only；真钱操作必须人工
  - 单标的权重 ≤ 10%；现金 ≥ 10%
  - 连续 3 期跑输基准 → 强制策略审查
risk_budget: {max_drawdown: 0.15, max_turnover_per_cycle: 0.30}
approval_points:
  - 调仓建议: 自动（纸面）
  - 真钱执行: 人工
  - charter/策略自修订: 人工+门禁
cadence: weekly
truth_sources: [csv://history/cn300.2020-2026.csv]
evaluation:                    # 评估域声明（机制级原语，见 2.7）
  domain: paper-performance
  metrics:
    - {name: 周期收益vs基准, direction: gt, source: history-replay}
    - {name: 回撤, direction: gte, budget: -0.15, source: portfolio}
  degradation: 无真值时降级声明，显式标注，不编造
```

### 2.2 memory/

```
memory/
├─ hypotheses.jsonl    # 假设台账：{id,陈述(可证伪),依据,状态[open/confirmed/falsified],周期,前向引用}
├─ decisions.jsonl     # 决策日志：append-only，{id,cycle,提案,依据,gate结论,执行摘要,eval,前向引用}
├─ pains.jsonl         # 痛点台账：{id,症状,频率,影响,根因,行动,预期指标,状态,证据,row_id}
└─ lessons.md          # 教训库：周期复盘沉淀，可修订但留修订记录
```

- 纠偏规则：假设被推翻不删除，新条目 falsified 并指向旧条目；决策日志永不修改；
  痛点关闭必须附证据，未治愈的痛点持续挂账；追加经 ledger_append 助手（唯一行身份）。

### 2.3 truth/

- 接口：`truth/fetch(project_id, cycle) -> {data, integrity_sha256, source_meta}`；只读。
- 校验：sha256 完整性 + 来源元数据；失效 → 该周期标记 `truth=unavailable`，产物显式标注
  "无真值模式（本次不构成演化信号）"，**不降级为编造**。
- 回放实现：本地 CSV 切片器（零成本、可复现）；近实时为可选适配器。

### 2.4 cycle/（节奏与六步）

- 白名单模板：`daily` / `weekly` / `event`（事件驱动：新数据/新反馈/发布完成）。
- 每周期六步（映射现有组件）：
  1. 观察：truth.fetch + 评估域评分 + 痛点台账 TOP-N + 上期 memory 摘要
  2. 提议：proposer 产出本周期提案（必须声明治哪个痛点或显式声明"探索"）
  3. gate：gate_review 裁决（规则层优先；charter 约束在此强制）
  4. 执行：code_sandbox（L1；纸面盘 = 计算与记录，不动真钱）
  5. 记录：decisions.jsonl 追加（含 eval: expected/actual/delta）+ observe.csv + audit/
  6. 复盘：差值 → 痛点回写（关闭/升级/保持）→ lessons.md 沉淀 → 下周期输入

### 2.5 policy/（领域化，风险分级）

| 域 | 自动 | 审批点 | 熔断 |
|---|---|---|---|
| 投资（纸面） | 观察/建议/回测/记录 | 真钱执行 | 回撤>风险预算→只读模式 |
| 交付物（网站/报告/游戏） | 草稿/构建/测试 | 线上发布 | 可用性<阈值→自动回滚+审查 |
| 通用 | 记忆追加 | charter 自修订 | 四锁关停 |

### 2.6 audit/

- 每周期：{cycle, truth_hash, proposal, gate, execution, decision, outcome_vs_baseline, lessons}
- 与 SUPPLYCHAIN-*.json 同风格；人工可导出"为什么当时这么做"的完整链。

### 2.7 评估与回写机制（评估域抽象，机制级原语）

- **定位**：完整持久化项目管理的内建原语。通用回路不因场景而异，变化的是**评估域**。
- **通用回路**（并入 cycle 六步）：
  ```
  观察（truth.fetch + 评估域评分） → 提议（必须声明痛点或显式声明"探索"）
  → gate → 执行 → 记录（eval: expected/actual/delta）→ 复盘（差值→痛点回写：关闭/升级/保持）
  ```
- **痛点台账**：memory/pains.jsonl（append-only；状态迁移=新行引用 pain id）。
  痛点 = 频率 × 影响打分聚合的失败/反馈；关闭必须附证据。
- **独立制衡**：痛点闭合/进展的证据引用由确定性验证器（文件存在/run_id/哈希）审计；
  事件弧线由角色分离复核人审计（只允许基于事实记录判断，短输出；LLM 失败回退确定性复核）；
  复核 concern/disagree 升级新痛点，收敛判定人工裁决。
- **评估域示例表**（表象随场景，机制不变）：

| 场景 | 评估域 | 指标示例 | 真值 |
|---|---|---|---|
| 投资 | performance | 收益vs基准、回撤、风险调整收益 | 行情（历史回放优先） |
| 网页（获客目的） | traffic/conversion | 访问量、转化率、留存率 | 分析探针 |
| 网页（展示目的） | showcase | 真值一致性、反馈数、迭代频率 | 仓库状态 + Issues |
| 网页（纯美工） | aesthetic | 人工评审/品牌一致性 | 人工评审 |
| 底座自身 | process-health | 回归通过率、dispatch rc、痛点关闭率 | 台账 + 日志 |

- **铁律衔接**：真值先于自动化——接不上真值的指标显式降级，不编造；人机分界按风险——
  发布/真钱类评估仍人工复核。

### 4.1 运行态闭环（2026-09-13，10 阶段调度）

七段调度已扩展为 10 阶段，每 4 小时自动执行：

```
pre-health → propose → gate → post → cleanup → observe
→ 5a project_selfcheck（管线自体检：快照+漂移+健康信号）
→ 5b project_site_gen（展示站真值驱动刷新）
→ 6a project_verify_pains（痛点证据确定性验证）
→ 6b project_dual_review（独立复核，节流：无新事件跳过）
→ advice → post-health → 7a project_regression（8 项过程不变量）→ dashboard
```

会话职责收敛为：提案 + 人工门禁。"用系统演化系统"由演示态转为运行态。
