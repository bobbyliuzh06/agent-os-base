# PATTERN — 经验库抄答案导致轨迹退化（wiki-answer-copy）

## 类型
failure

## 现象（可观察的表现）
- 执行 agent 直接读 wiki 照抄 → 轨迹中推理链变短、工具调用减少；
- 蒸馏出的新 pattern 信息量下降、与旧 pattern 高度同义；
- 技能长期无实质演化，回归得分在高原期后缓慢下滑。

## 触发条件（何时会出现）
- 新任务与历史任务高度相似（"上次就这么干的"）；
- 时间压力下"查一下更快"的诱惑；
- wiki 规模变大后检索成本低于重新推导。

## 根因
- 抄答案绕过了"重新推导"，raw 轨迹失去新信息；演化循环（raw→wiki→skill→gate）依赖轨迹信息量作为燃料，抄答案等于短路主引擎；
- 经验库从"参考"滑向"答案"，执行与经验隔离（宪法第 3 条）被侵蚀。

## 应对措施（可复用的步骤/规则）
1. 执行与经验隔离铁律：执行 agent 只加载 `skills/`，不直读 `wiki/`；wiki 访问限定维护/提案角色；
2. `trace-distill` 强制"新颖性检查"：与现有 pattern 完全同义的候选不新建，合并并记录，防同义堆积；
3. 轨迹信息量审计：定期检查执行轨迹的推导长度、工具调用多样性、新结论占比，把"信息量退化"作为演化健康指标；
4. 执行 agent 引用规则面（宪法/GATE/技能）是允许的——规则面不是经验面，不算抄答案。

## 适用条件与例外
- 维护者/提案者读 wiki 不触发（这是他们的合法输入）；
- 执行 agent 读宪法、GATE、当前生效技能不触发。

## 证据轨迹
> 冷启动声明：无真实项目轨迹。依据 = `SEED/wikiskill.summary.md`（执行期隔离原则；ablation 数据：移除持久 wiki 后 63.7% → 48.7%，反向印证经验库是主引擎，抄答案即短路主引擎）+ 自指论证。回补期限见 PROPOSAL.md。

## 跨领域适用性评估
- 原领域：软件 agent 执行
- 可迁移至：任何知识库驱动的执行组织（客服 SOP、审计底稿、运营手册——老员工"凭经验照抄"同样导致组织学习停滞）
- 抽象层级：高（执行与知识库隔离的组织原则）
