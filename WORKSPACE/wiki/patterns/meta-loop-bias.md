# PATTERN — 元流程自身带偏（meta-loop-bias）

## 类型
failure

## 现象（可观察的表现）
- BASE 演化多轮后，近期项目领域的 pattern 占比压倒性升高；
- 回归集长期未更新，老领域探针得分悄然下滑而无人在意；
- 元流程某一步长期无人挑战——"演化机制自身也可被演化"（宪法第 4 条）从未被使用过。

## 触发条件（何时会出现）
- 连续多个同领域项目回填；
- 回归探针集冻结，所有新经验都来自近因；
- 机制自指盲点：循环优化它眼前的数据，没有人优化循环本身。

## 根因
- 演化循环对近因证据天然过拟合（最近的失败最容易被蒸馏）；
- 回归集一旦冻结就从"检验器"退化为"摆设"，而探针设计本身没有轮换机制；
- 元流程的每一步（pattern 怎么写、验证集怎么留）也可能带偏见，但缺一个定期体检的触发点。

## 应对措施（可复用的步骤/规则）
1. 回归探针集定期轮换 + 基线 tag 对比（每轮回填打 tag，旧基线永远可回退比对）；
2. 周期性"元流程体检"：每 N 轮（v0.1 建议 N=3，待校准）强制对照本 pattern 等 meta-* 条目检查一次演化机制健康度；
3. 宪法修正案流程保留并作为常态出口（第 4 条不是摆设，是机制的自愈通道）；
4. wiki 持久、不随 skill 回滚：失败经验永远保留，防止"回滚时把教训一起删了"。

## 适用条件与例外
- 冷启动第一轮不触发（无历史数据）——本 pattern 是预防性设计，不是本轮已发生的事故；
- 探针轮换本身也要防"为轮换而轮换"：轮换需记录理由与新旧探针对照。

## 证据轨迹
> 冷启动声明：无真实项目轨迹。依据 = `SEED/dialogue.distill.md` 共识 4（演化机制自身也可被演化）+ `SEED/scaling.summary.md`（结论是"特定任务分布上的经验规律"，防过拟合）+ 自指论证。回补期限见 PROPOSAL.md。

## 跨领域适用性评估
- 原领域：agent 演化系统
- 可迁移至：任何持续改进体系（质量管理 PDCA 形式化、产品迭代复盘、审计整改跟踪）
- 抽象层级：高（自我修正循环的自盲点防护）
