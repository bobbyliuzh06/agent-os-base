# route-intake — 任务路由与底座适配判断（v0.1 自举候选改进版）

## 目的

把任意领域的新需求映射为"可执行方案 + 技能集"，并产出**是否需提底座修改**的信号。

相对种子版（`skills/route-intake`）的改进：

1. 新增**领域抽象映射**步骤（反工程师人格污染，见 pattern `seed-persona-lock`）；
2. 底座适配判断成为**显式必答输出**（供第六维 E2 查验）；
3. 全程**技能版本留痕**（供第六维 E1 查验）；
4. 明确本技能输出的是**待验证假设**，阈值须由真实项目数据校准（见 pattern `meta-loop-bias`）。

## 适用角色与领域

任何角色/领域。非软件任务必须走领域抽象映射，不得套用软件术语。

## 输入

用户需求（任意表述形式，含糊时先澄清）。

## 步骤

1. **留痕**：记录技能版本戳 `route-intake@<版本>`；路由记录最终写入 `WORKSPACE/raw/route-<task>.md`（不可变）。
2. **澄清**（借鉴 grill，先质询再动手）：向用户确认目标、边界、输入/输出、成功判据、容错要求、HITL 需求；未明确的不猜测、不补全。
3. **领域抽象映射**：若为非软件领域，把软件种子概念翻译为领域等价物，禁止直接沿用：
   | 软件概念 | 通用思维流 | 领域等价物示例 |
   |---|---|---|
   | TDD | 先定义可验证成功标准，再执行，再按反馈修正 | 供应链：先定义"响应达标判据" |
   | issue 垂直切片 | 可独立验收的最小工作单元 | 运营：单条 SOP 修改项 |
   | ADR | 不可逆决策留痕（附备选与被否决理由） | 合规：审批规则变更记录 |
   | 复现/最小化 | 把现象收窄到可验证的最小条件 | 客服：最小可复现投诉样本 |

   若某概念在该领域无等价物，标注"种子概念不可迁移"，作为适配判断输入。
4. **任务属性表**（假设集，可被项目数据校准，来源 `SEED/scaling.summary.md`）：
   | 属性 | 取值 | 倾向 |
   |---|---|---|
   | 并行度 | 高/低 | 高 → 可考虑集中编排 |
   | 串行依赖 | 高/低 | 高 → 优先单 agent |
   | 工具密度 | 高/低 | 高 → 控制 agent 数 |
   | 错误代价 | 高/低 | 高 → 必须集中校验 + 回放 |
   | 可独立验证 | 是/否 | 是 → 可派发专家 |
   | 是否软件工程 | 是/否 | 否 → 走领域抽象映射 |
5. **拓扑建议**（保守默认：单 agent；详见 `WORKSPACE/route-design.md`）：
   - 串行依赖高，或错误代价高且无集中校验设计 → 单 agent
   - 并行度高 + 可独立验证 + 错误代价低/中 → 集中编排（1 orchestrator + N 专家）
   - 工具密度高 → 单 agent + 工具，不盲目加人
6. **技能集映射**：从 `skills/` 选出适用技能；无匹配 → 标记"待创建"，纳入任务结束时的 PROPOSAL。
7. **底座适配判断（必答，写入路由记录）**：
   - 不适配条件：① 领域完全不在种子覆盖范围内且无等价抽象；② 任务属性表有 ≥2 项无法用现有维度表达；③ 执行中反复绕过铁律才能推进。
   - 输出格式：适配/不适配 + 理由 +（不适配时）建议修改对象类型（pattern | skill | architecture | constitution）。

## 验证判据

- 每个新任务都先走本技能再执行
- 路由记录落在 `WORKSPACE/raw/route-<task>.md`，含技能版本戳与适配判断（第六维 E1/E2 可机械查验）
- 非软件任务的路由记录中出现领域抽象映射，且无软件术语直接套用

## 回滚方案

拓扑/技能集/适配判断均为待验证假设，由任务轨迹反馈修正；本技能自身的修改走 GATE A 级（skill-modify），回滚即恢复上一版 SKILL.md，wiki 不回滚。

## 注意事项 / 反模式

- 反模式：跳过留痕直接执行；对非软件任务直接输出"写测试/开 issue"（人格污染）；把本表阈值当静态规则库。
- 冷启动诚实：本技能尚未经真实跨领域项目验证，定性为 v0.1 自举候选，不宣称"已通用"。
